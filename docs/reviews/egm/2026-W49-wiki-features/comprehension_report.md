# Stage 6: Comprehension Test 보고 (설계서 단독 읽기, 1-278행)

검토자: egm-comprehension. 이 단계는 설계서만 읽는다(컨텍스트 파일 없음).
참고: 검토자는 일부 항목을 한 줄로 줄여 적었다. 아래는 결과 전문의 정리본이며, 판단 내용은 바꾸지 않았다.

**What this proposes**

W49 주간(11/23~11/29)에 위키백과의 특수 문서 190개와 편집·읽기·정책 기능을 하나씩 판정했다고 한다. 판정은 채택, 변형, 이미 있음, 보류, 비채택 중 하나다. 판정 기준은 세 가지다. 운영자나 검토자 권한 기능은 쓰지 않거나 규칙 계산으로 바꾼다. 신뢰도는 기여 원장에서만 올린다. 조회수는 점수에 넣지 않는다.

스키마 변경 없이 가능한 작업만 W49에 넣는다. 작업은 W1(리비전 비교·고정 링크·되돌리기 버튼), W2(위키링크 해석), W3(`/contribute` 기여할 거리와 토막 문서), W4(편집 필터와 계산형 변경 태그), W5(작은 기능 묶음)다. 스키마가 필요한 기능은 W50 이후로 미룬다. 10절은 11-22에 순서를 바꾼 내용이다. R 수용 코드 묶음을 맨 앞에 두고, W4를 목요일로 옮기고, C와 `useOptimistic`에 W49 마감을 붙이고, S·K는 W50으로 확정했다.

**How the existing system works, per this document**

이 시스템은 상품·문서(Item)를 분류 갤러리(대·중·소 분류)에 담는 위키형 서비스로 보인다. 문서에는 리비전 기록(`EditHistory.snapshot`)과 토론(`TalkComment`)이 있고, 점수는 투표로만 계산한다(ADR 0001). 되돌리기 API는 있으나 화면 버튼이 없다. `[[ ]]` 는 지금 검색 링크로만 바뀐다. 편집 충돌은 409만 반환한다. 보호 수준은 규칙으로 계산한다. `/recent` 와 분류 갤러리 팔로우(`scope=following`)가 있다. `/u/[id]` 는 기여 개수만 보여 준다. 로그인은 OAuth이고, 제재는 `suspendedUntil` 로 최소한만 있다. `Notification` 모델은 이미 있다. `npm run build` 는 `db:push` 가 적용되지 않아 `P2021` 로 실패하는 상태다. 그래서 모든 완료 항목이 "build 미확인"으로 남는다.

**Findings**

1. **Blocker** (0절 대 5절) 판정 집계 수치가 문서 안에서 맞지 않는다. 합계가 77행인데 "무관한 묶음 9개"가 77 안인지 밖인지 말하지 않는다. "있음·비채택", "변형/비채택"처럼 판정이 둘인 행의 집계 규칙이 없다. 변형 31의 나열을 세어도 31이 되지 않는 것 같다. 보류 4(넘겨주기 2, 공개 API, 라이선스)와 3.1·3.2절의 넘겨주기 행이 일치하는지 확인할 수 없다.
2. **Blocker** (0절 원안 순서, 6절, 10절) 작업 순서가 세 곳에 달리 적혀 있다. 원안 ①~⑤가 W1~W5 와 같다고 밝히지 않는다. 6절은 "10절 우선"이라면서 원안 순서와 이유를 길게 남긴다. 10.3 은 W1·W2 가 끝났다고 하는데 0절·6절은 W1~W4 를 하는 것처럼 쓴다. 0절의 "다섯 가지"와 10절의 작업 목록(R, C, `useOptimistic`, W3, W4, W5)이 다르다.
3. **Blocker** (10.3 요일표) 표가 10.2 의존 관계와 맞물리지 않는다. "G 가 됐을 때" 열에서 C 의 시작일이 없는데 수요일에 C 가 마감된다. 열 이름의 G 가 정의되는 곳을 찾기 어렵다.
4. **Blocker** ("G", "G-사람", "G-대화형", "C", "S", "K", "M", "R", "B", "P1·P2·P3") 한 글자 약어에 의존하지만 정의가 없다. G 는 0절 괄호에 처음 나오고 10.1 #2 에서야 풀린다. K 는 10.6 에서야 `ink` 치환임을 짐작한다. 규모 표기 S/M/L 이 정의되지 않고, 같은 글자 S 가 규모와 출처 구조 두 뜻으로 쓰인다(7절 표에서 "출처 구조 S"의 규모가 L). B, M1, P1~P3 도 정의가 없다.
5. **Major** (참조 문서들) 핵심 판단과 구현 내용을 다른 파일에 맡기고 요약을 주지 않는다. 10.4 의 "답신 1~6", "1·2"가 무엇인지, 10.5 의 C 알림 3종 조건이 무엇인지 이 문서만으로 알 수 없다. 경로가 디렉터리 없이 파일명 일부로만 주어진 곳이 있다.
6. **Major** (1절 "일반 지식 기준") 표시가 4절 제목에만 있고 3절 각 행에는 없다. Edit Recovery, Edit checks 등의 출처를 알 수 없다. `Help:Contents` 를 요약으로만 읽은 상태에서 "채택" 판정의 확실성을 가늠할 수 없다.
7. **Major** (1절, 2절) 2절의 ○ ◐ ● 기호에 범례가 없다. "그대로" 같은 값이 섞여 있다. "되돌리기"의 10/12 열과 지금 열이 같은 ◐ 로 다른 뜻을 가진다. 보류와 기호의 관계가 없다.
8. **Major** (6절 머리말 P2021·build) "build 미확인"이 `[x]` 완료와 어떻게 공존하는지, 어떤 테스트로 대신 검증하는지 적혀 있지 않다. 근거 "11-18 dev.md:14"에 경로가 없다.
9. **Major** (3.1절 Orphaned pages) "상황 갤러리에 연결되지 않은 분류"가 정의되지 않는다. 분류 갤러리·대중소 분류·소분류가 같은 것인지 구분되지 않는다. "테마→분류 갤러리" 변경 흔적만 10.4 에 있다.
10. **Major** (W2 `resolve` 계약) `many`/`none` 의 href 형식과 R-1 의 "30건 밖의 정확 일치"가 나오는데 검색이 30건으로 제한된다는 전제가 적혀 있지 않다.
11. **Major** (W3 "만들어 주세요") 전 문서 스캔 비용에 `ponytail:` 한계 표기가 없다. "ACTIVE 불일치"(10.1 #1)가 무엇과 무엇의 불일치인지, ACTIVE 의 의미가 없다.
12. **Major** (W3 "답변 없는 추천 요청") 3.1절 표와 5절 집계에 없고, 위키백과의 어느 기능에 대응하는지, 추천 요청이 무엇인지 설명이 없다.
13. **Major** (2절 편집 요청 "승격", 3.5절 "있음·비채택") 0절은 처음부터 편집 요청을 W50+ 로 넣는데 2절은 "승격"이라 한다. 무엇에서 무엇으로 올렸는지 불명확하다. 한 행에 두 판정이 섞인 행이 있다.
14. **Major** (표 구조) 3.3·3.6·3.7·4절에는 "큐" 열이 없고 괄호 (⑤), (④) 로 흩어졌다. "W50 (M)", "W50+ (낮음)" 같은 다른 표기를 쓰며 "낮음"이 우선순위인지 규모인지 정의가 없다.
15. **Major** (W4 `checkEdit`) 3.4절의 "걸린 시도는 저장하지 않는다. 경고만 보여 준다"가 block 인지 confirm 인지 모호하다. 위험 항목의 "block 이 아니라 confirm" 구분이 일관되지 않는다. `changeTags` 의 `revertOfRevision` 설명이 없다.
16. **Nit** 5절은 2절의 되돌리기 버튼이 "별도"라 하나 어디에 세는지 말하지 않는다.
17. **Nit** 3절 제목 괄호 숫자의 합이 190 인지 확인할 방법이 없고, "원문 그대로"라 하면서 3.7절은 요약한다.
18. **Nit** `파일:줄` 근거에 커밋 해시가 없어 어긋날 수 있다. 10절만 해시를 쓴다.
19. **Nit** "큐"는 6절 작업 번호라 하나 6절 제목은 W1~W5 이고 표는 ①~⑤ 를 쓴다. 대응은 짐작해야 한다.
20. **Nit** 한 행에 항목 20개 이상을 늘어놓은 행(3.3, 3.6절 마지막 행)은 개별 근거가 없고, Special:* 영어 이름 대부분이 풀이 없이 나온다.
21. **Nit** 3행 "일요일(11/22) 무인 설계 세션에게" 안내는 처음 읽는 사람에게 맥락이 없다. "무인 설계 세션"과 10절의 관계, `egm-review.sh` 연결이 설명되지 않는다.
