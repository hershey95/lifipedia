# Stage 5: Initial Zoom Out 보고 (2026-W49-wiki-features.md, 1-278행)

검토자: egm-zoom-out, egm-inventive-catalyst (각각 새 컨텍스트). 컨텍스트: GLOSSARY.md, ADR 0001, ADR 0002, ROADMAP.md.
범위 분할: 설계서에 표준 구현 계획 헤더가 없어 6절(153행)을 경계로 잡았다. FeatureRange 1..152, DetailedRange 153..278.

## A. Zoom Out (판정: 조건부 통과, Blocker 없음)

### Major
- **ZO-M1 (158-172, 222행)** 이미 끝난 W1·W2 가 "앞으로 할 일" 설계로 6절에 남아 있다. 코드에 `revision.ts:11 parseRevRange`, `markdown.ts:42 extractWikiLinks`, `wikilinks.ts:27 findBacklinks` 가 이미 있다. 완료와 미완료를 구분할 수 없다.
- **ZO-M2** 설계서가 구현 세부까지 내려갔다(167행 `resolve` 반환 모양과 쿼리 파라미터, 162행 뒤집기 동작, 261행 `min-w-0`·폴백 값, 267행 `updateMany` 구문). 경계와 데이터 흐름만 남기면 절반 길이로 충분하다.
- **ZO-M3 (174-179행)** W3 `/contribute` 가 6종 목록, 분류 필터, `unstable_cache(300)` 까지 한 번에 잡았다. 병목 확인 전 캐시다. 토막 문서와 "만들어 주세요" 두 종으로 시작하는 편이 낫다.
- **ZO-M4 (169, 176행)** 역링크 LIKE 전수 탐색의 "1만 개" 기준이 W3 의 전수 스캔(`extractWikiLinks` 를 전 문서에 실행)에는 적용되지 않는다. 링크 테이블을 앞당길 판단 기준이 없다.

### Nit
- ZO-N1 (6, 146-151행) 190개 판정 숫자가 스스로 합계가 안 맞는다고 인정한다.
- ZO-N2 (12-13행) `Help:Contents` 를 요약으로만 읽었다. 4절 일부는 기억 의존이다.
- ZO-N3 (3-4, 154-156행) 지난 일회성 지시와 원안 순서 문단이 남아 있다.
- ZO-N4 (183-190행) `checkEdit` 의 block 은 `httpUrl`(`src/lib/api.ts:40`) 검증에 붙이는 편이 낫다. hint 는 클라이언트 문구로 충분할 수 있다.
- ZO-N5 `content-check.ts` 는 W3 `stubReasons` 와 겹치지 않는다. 재사용 지점(`buildDiff`, `changeKind`, `httpUrl`)은 적절하다.

## B. Inventive Catalyst

### A. 모순과 낡은 문장
- **IC-A1 [Major] (3행 대 154행·10.4절)** 3행은 "순서만 조정"인데 10절은 R-1·R-2 새 작업과 W4 범위 확대를 넣었다. 154행은 "W1~W5 설계는 그대로"라고 하나 10.1 #3 은 W4 를 바꾸고, W4 본문(182-190행)에는 반영이 없다.
- **IC-A2 [Major] (163, 168, 169행 대 261행)** W1·W2 본문과 R-1 이 충돌한다: 누락 필드 폴백(빈 값 vs 현재 값), 역링크 필드(1개 vs 3개 OR), 리졸버 필터(`isRemoved` vs `+ACTIVE`). 앞쪽만 읽으면 수용한 결함이 되살아난다.
- **IC-A3 [Major] (59행, 165-172, 219행)** 동명 문서 링크를 기여할 거리로 보여 주지만, 중복 이름 중 하나를 가리키는 문법이 W2 에 없어 기여자가 그 일을 끝낼 수 없다. 제안: `[[이름@소분류]]` 같은 한정 인자(비용: 문법 증가, 소분류 이름 변경 시 깨짐, 137행 틀 거부 논리와 긴장).
- **IC-A4 [Major] (9, 200-209행)** 헤더는 "스키마 필요"인데 감사 표시(205행)·문서 비교·링크 미리보기·충돌 해결(208행)은 스키마 없음이다. 이들은 W49 남는 칸에 들어갈 수 있다. 7절을 둘로 나눈다.
- **IC-A5 [Major] (31, 49, 61, 122, 203, 206행, ROADMAP 8·53·89-90행)** 문서 이동·병합이 31행 "후순위 유지"와 203행 W50+ 첫 줄로 엇갈린다. ROADMAP 90행은 로드맵 밖이라 한다. 편집 요청(206행)은 누가 수락하는지 정의가 없고, 122행의 사람 권한 비채택과 부딪친다. ROADMAP 8행은 충돌 해결을 선행으로 두나 208행은 병렬이다. 제안: 수락을 규칙 계산(신뢰도 기준 N명 동의 또는 72시간 무이의)으로 통일(비용: 투표 몰이 위험, 지연).
- IC-A6 [Nit] (156행) "새 컬럼은 S 하나뿐", "하루 2개, 최대 8칸" 이 10절과 어긋난다.
- IC-A7 [Nit] Orphaned(43행)·동명 문서 링크(59행)가 W3 목록(176행)에 없다. 40행은 필수 "절들"이라 하나 175행은 `## 출처` 하나만 본다.
- IC-A8 [Nit] 267행 `best=1` 은 GLOSSARY 의 "베스트" 금지·용법과 섞인다(`concept=1` 권고). 문서 단위 주시를 넣으면 GLOSSARY 주시목록 정의 갱신이 필요한데 7절에 없다.
- IC-A9 [Nit] (6, 147, 101, 121행) "190개를 하나씩 판정" 표현과 한 행에 판정 둘인 행의 집계 기준이 불명확하다.
- IC-A10 [Nit] (74행 대 98·121행) Active users 는 부풀리기 위험으로 비채택하면서 Impact(내가 고친 문서 조회수)는 허용한다. 위험 종류가 같다.

### B. 거짓 타협과 해결 변환
- **IC-B1 [Major] (156, 244-254행)** "build 미확인" 한 주. 운영 DB 반영과 build 가능 여부를 한 덩어리로 다룬다. 제안: 무인 세션이 `DATABASE_URL=file:/tmp/<id>.db` 임시 DB 에 `db push` 후 `npm run build`(운영 DB 는 G-사람이 그대로 맡음). 한계: 빈 DB 는 데이터 의존 prerender 를 검증하지 못하고, Bash 허용 기록이 필요하다(G-대화형 영역).
- **IC-B2 [Major] (169, 176, 43, 59행)** W3 이 같은 링크 정보로 다섯 가지를 계산하는데 문서별 LIKE 면 Orphaned 가 O(N²). 제안: 캐시 안에서 전 문서를 한 번 훑어 정방향 맵을 만들고 뒤집어 역방향 맵을 만든다(스키마 변경 없음). 한계: 캐시만큼 오래된 값, 메모리 적재.
- **IC-B3 [Major] (85, 188행)** 읽을 때 계산하는 변경 태그는 `/recent` N+1 위험과, 기준 상수 변경 시 과거 태그가 소급 변경되는 문제(GLOSSARY 점수의 시점 고정 철학과 같은 계열)가 있다. 제안: 직전 스냅샷 일괄 `in` 조회, 기준 상수 버전 표기, 다음 스키마 때 `EditHistory.tags` 추가.
- **IC-B4 [Major] (186-190, 111행)** 편집 필터가 막기만 하고 푸는 쪽이 없다. `confirmed: true` 는 클라이언트 값이라 API 직접 호출이면 무의미하고, hint 를 보일 경로가 없다. 제안: `checkEdit` 을 클라이언트에서도 호출해 hint 표시, 큰 가격 변동의 해제 조건을 "같은 편집에서 출처 URL 증가"로(비용: 가짜 URL 우회, 판정 불일치 가능).
- **IC-B5 [Major] (229, 215, 261행)** URL 검증을 W4(목)에 합쳐서 이미 나간 `?rev=` 렌더가 약 4일간 스냅샷 URL 을 검증하지 않는다. 쓰기 시점 block 은 과거 스냅샷을 막지 못한다. 제안: `httpUrl` 과 차단 도메인 상수를 `url-policy.ts` 로 먼저 분리해 R-1 이 렌더 시 거르고 W4 가 재사용.
- IC-B6 [Nit] (176, 101, 37행) 5분 캐시 때문에 고친 토막이 목록에 남는다. 제안: edit 성공 시 `revalidateTag`.

## 이 단계 종합 우선순위
1. (Major) 8절 215행 "`?rev` 검증" 과 R-1 의 URL 필드 검증 부재 (IC-B5)
2. (Major) W1·W2 본문 대 R-1 충돌, 완료 표시 없음 (ZO-M1, IC-A2)
3. (Major) 동명 문서를 해결할 수단이 없음 (IC-A3)
4. (Major) W3 범위 과다·캐시 선행·전수 스캔 (ZO-M3, ZO-M4, IC-B2)
5. (Major) 3행 지시와 10절 범위 불일치, 7절 분류 기준 (IC-A1, IC-A4, IC-A5)
