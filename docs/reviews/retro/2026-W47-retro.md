## 2. 계획과 달라진 판단과 이유

1. **W47 큐를 B·C·S·K 에서 T1~T3·V1 로 교체.** 사용자가 11-08 에 "갤러리가 너무 크다. 쇼핑몰처럼 대·중·소분류, 상황 갤러리가 상단, 인기 분류가 위로"를 지시했다(taxonomy 설계서 지시 절). 사용자 지시가 설계서보다 우선이라 판단은 타당하다. 다만 `community-sources` 설계서는 8.1 요일표를 고치지 않았고 PROGRESS 가 우선한다는 점만 PROGRESS 로 전해진다. 두 설계서의 요일표가 어긋난 채 남아 있다.
2. **조회수를 순위가 아니라 인기 산정의 보조 항으로 분리(V1).** ADR 0001(조회수는 순위 점수에 넣지 않음)을 지키려고 `ranking.ts` 와 분리된 `popularity.ts` 에 조회 항을 두고, 데이터가 30일 이상일 때만 쓰게 했다. 근거는 dev 보고서 11-11·11-12 이며 ADR 해석은 사용자 확인 대기다.
3. **인기 점수의 "가중투표"를 참여량(UP·DOWN 구분 없음)으로 구현.** 설계서가 명시하지 않아 구현 세션이 정한 해석이다(11-11, 11-12 연속 사용자 결정 요청). 순추천(UP−DOWN)이 맞으면 `popularity.ts` 를 고쳐야 한다. 이틀째 답이 없다.
4. **`vid` 쿠키를 서명하지 않음(V1).** 설계는 HMAC 서명이지만 비밀키 환경변수 신설이 필요해 보류하고 IP 분당 한도로 보완했다. 위조해도 자기 중복 제거만 우회한다는 평가이며 사용자 결정 대기다.
5. **T2·T3 를 쪼개 부분 완료로 표시.** 데이터(`CATEGORY` 행, 시드)가 없어 `unstable_cache`·상위 요약을 시험할 수 없다는 이유다. 합리적이지만 `[x]` 의 의미가 "코드는 있고 데이터 없이 시각 확인 못 함"이다.
6. **무인 세션의 `scripts/` 금지 때문에 실행 래퍼를 만들지 않음.** 재배치(T1)·시드 import(T3) 두 개가 막혔다. 순수 함수와 테스트까지만 만들어 "나중에 2줄 래퍼"로 넘기는 판단은 일관되나, 이 래퍼 없이는 T1~T3 가 운영 데이터에 닿지 않는다.
7. **안티의 `content/*.json` 쓰기 차단 4일째를 그대로 둠(11-13 daily).** 대화형 Claude 가 직접 반영하는 쪽으로 기울었으나 결정되지 않았다. 낡은 가격 2건(힐레베르그 2,034,050→2,225,490, 써머레스트 167,200→190,000)과 크레모아 재입고 인용 2건이 공개 JSON 에 남아 있다.
