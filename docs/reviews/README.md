## 피드백과 수용
- 안티가 Claude 를, Claude 가 안티를 서로 리뷰한다. 대상: Claude 의 최근 24시간 설계·코드, 안티의 콘텐츠.
- 받은 쪽은 항목마다 **수용 / 부분 수용 / 거절 + 이유**를 `*-reply.md`(안티) / `*-feedback-response.md`(Claude)로 남긴다. 맞장구로 전부 수용하지 않고, 근거가 부실하면 이유를 달아 거절한다.
- 큰 변경(스키마, 서비스 철학, 우선순위)은 반영하지 않고 사용자 결정 사항으로 올린다. 철학 위반 지적은 최우선.
- 상대 결과물을 리뷰어가 직접 고치지 않는다. 영역: 코드·설계 = Claude, 콘텐츠·분류 시드·리뷰·디자인 감사 = 안티.

## 리뷰 규칙
1. 아래 템플릿의 표로 쓴다. 자유 서술·장문 금지.
2. 범위는 하루치 변경분. 전체를 훑지 않는다.
3. 맞장구 금지: 지적 3개 이상, 정말 없으면 "확인한 항목"을 구체적으로 나열한다. "문제 없음"만 쓴 리뷰는 무효.
4. 자동 반영 금지: 리뷰는 의견이다. 반영 여부는 받은 쪽이 판단해 기록한다.
5. 운영자 큐레이션 금지 철학(투표·점수 임의 조작 금지)을 어기는 제안은 철학 위반으로 표시하고 채택하지 않는다.
