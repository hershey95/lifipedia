# 상황 갤러리 × 제품 분류 트리 설계 (2026-11-08, 사용자 지시)
## 지시 (원문 요지)
- 지금 갤러리가 너무 크다. 쇼핑몰처럼 대·중·소분류로 들어가야 한다.
- **상황별 갤러리가 대분류보다 상단**에 있고, 그 안에 중·소분류 갤러리들이 상황에 맞게 배치된다. **인기 있는 중·소분류가 위로** 오른다. 그러면 시기별·테마별로 무엇을 사고 비교해야 하는지 알 수 있다.

## 1. 모델 (Theme 를 두 종류로 나눈다)
| | 상황 갤러리 `SITUATION` | 분류 갤러리 `CATEGORY` |
|---|---|---|
| 예 | 20대 자취·독립, 캠핑·차박, 신혼집 | 캠핑 > 텐트 > 1~2인 백패킹 텐트 |
| 문서 소유 | **없음** (분류를 연결만 한다) | **리프(소분류)** 가 문서를 갖고 순위를 매긴다 |
| 계층 | 기존 허브(5개)가 상황을 묶는 상위 메뉴 | `parentId` 로 대→중→소 (깊이 3) |
| 순위 | 연결된 분류의 요약만 표시 | 저가·중가·고가 Top 3 (같은 종류끼리만 비교) |

- 스키마: `Theme.kind` (`SITUATION | CATEGORY`, 기본 `SITUATION` 으로 기존 14개+허브 5개는 그대로), 연결 테이블 `SituationCategory(situationId, categoryId, createdById?, createdAt, @@unique([situationId, categoryId]))`.
- `Item.themeId` 는 **리프 분류**를 가리킨다. 기존 17개 문서는 리프 분류로 재배치한다(마이그레이션 스크립트, 사람 확인 후 적용).
- 기존 URL 은 유지한다: `/theme/[slug]` 가 `kind` 에 따라 상황 페이지 또는 분류 페이지를 그린다. 새 링크 규칙을 만들지 않는다.

## 2. 인기 계산 (운영자 임의 가점 없음, 재현 가능)
`popularity(category, 30일) = Σ 가중투표(30일 내) + 2 × 편집 수 + 댓글 수` , 동점은 `followerCount`. 가중투표는 기존 랭킹 가중치를 재사용한다. 공식은 "인기 산정 방식" 페이지에 공개하고 순수 함수(`src/lib/popularity.ts`)와 테스트로 고정한다. 서버에서 계산하고 `unstable_cache(60초)` 로 캐시한다. 시기별 변화는 30일 창이 자동으로 만든다.

## 3. 화면
- 상황 페이지: 연결된 분류 갤러리 카드(분류 경로, 소속 문서 수, 인기 지표, 1위 문서 미리보기), 인기순. 카드가 없으면 "아직 연결된 분류가 없습니다" + 제안 링크.
- 분류 페이지: 경로(홈 > 캠핑 > 텐트 > 백패킹 텐트), 하위 분류 칩(중분류면 소분류 목록), 순위·목록·토론 탭(기존). 중분류는 하위 리프의 1위를 모아 보여준다.
- 문서: 경로가 `상황 / 대 > 중 > 소` 가 아니라 분류 경로만 쓴다(문서는 상황 소유가 아님). 소속 상황은 "이 제품이 나오는 상황" 칩으로 표시.

## 4. 연결을 누가 정하나 (철학 점검)
운영자 큐레이션 없음 → 초기 시드는 Gemini 가 쇼핑몰 분류 체계를 조사해 `content/taxonomy.json` 으로 제안(사실 조사). 이후 연결·분류 추가는 사용자 제안 + 기여 기준 충족 사용자 N명 승인(W48 이후, 기존 `Theme.status PROPOSED→ACTIVE` 흐름 재사용). 이번에는 시드만 반영한다.

## 5. 작업 순서 (PROGRESS W47 에 T1~T3 로 등록)
1. **T1 스키마·모델**: `kind`, `SituationCategory`, 마이그레이션 스크립트(문서 재배치, 임시 DB 에서 시험), 테스트.
2. **T2 분류 페이지·경로·상위 요약** + `popularity.ts`.
3. **T3 상황 페이지(인기순 분류 카드)** + 시드 import(`taxonomy.json` 검증 `content:check` 확장).
- DB 반영(`db:push`)·실제 문서 재배치는 사람이 한다(무인 금지).

## 6. 위험
- 분류 깊이·이름이 흔들리면 URL 이 바뀐다 → 슬러그는 한 번 정하면 불변, 이름 변경은 별칭(redirect)으로.
- 소분류가 너무 잘게 쪼개지면 문서가 0~1개라 순위가 안 선다 → 문서 3개 미만인 리프는 상위 분류 목록에 합쳐 보여준다(순위는 3개부터).
