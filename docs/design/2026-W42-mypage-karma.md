# 설계서: 마이페이지(/me) + Karma·뱃지 진행도 (2026-W42)
- 작성: Claude (초안, 일요일 Opus 가 다듬음) / 리뷰: Gemini (월요일) / 구현: Sonnet 월~목
- 상태: 초안 + Gemini 리뷰 반영(9절)

## 1. 현재 상태 (코드 기준)
- 공개 프로필 `/u/[id]` 가 있다: 뱃지, 신뢰도, 기여 수, 통계 4개, 작성 문서 Top10 (`src/app/u/[id]/page.tsx`).
- 신뢰도·뱃지는 `contributionCount` 에서 파생된다 (`src/lib/trust.ts`). 기여는 **문서 생성·편집에서만** +1 (`bumpContribution`, items/route.ts, items/[id]/edit/route.ts). 투표·댓글은 기여가 아니다.
- 투표 가중치 = 신뢰도 × (가입 후 `NEW_ACCOUNT_DAYS` 이내면 `NEW_ACCOUNT_MULTIPLIER`) (`voteWeightFor`).
- 없는 것: 로그인한 본인이 보는 화면(`/me`), 다음 뱃지까지 얼마나 남았는지, 내 한 표의 실제 영향, 내 활동 시간순 목록, 프로필(이름·소개) 수정, 팔로우한 테마 목록.

## 2. 목표
로그인한 사용자가 "내가 얼마나 기여했고, 그게 서비스에 어떤 영향을 주며, 다음에 무엇을 하면 되는지"를 한 화면에서 본다. **운영자 조정 없이 기여에서만 파생**되는 원칙(trust.ts 주석)을 유지한다.

## 3. 범위
### 포함
1. `/me` (로그인 필수, 비로그인 → `/signin?callbackUrl=/me`, `robots: noindex`)
   - **Karma 카드**: 뱃지, 신뢰도, 기여 수, **다음 뱃지까지 남은 기여 수와 진행 막대**, **내 한 표의 실제 가중치**(신규 계정 감쇠 포함, 해제까지 남은 일수).
   - **내 활동**: 작성한 문서 + 편집을 시간 역순으로 최근 30건 (기존 테이블에서 조회, 새 테이블 없음).
   - **내 투표**: 최근 30건 (아이템명, 찬/반, 당시 가중치).
   - **팔로우한 테마** 목록.
   - **프로필 수정**: 이름(1~30자), 소개(0~200자).
2. 헤더에 로그인 상태일 때 `/me` 링크 (`AuthButton`).
3. `/u/[id]` 는 공개용 그대로 두고, 본인이 보면 "마이페이지로" 링크만 추가.
4. `trust.ts` 에 순수 함수 추가: `badgeProgress(count)` → `{ current, next|null, remaining, percent }`. 테스트 포함.

### 제외 (이번 주 안 함)
- 기여 이벤트 로그 테이블, 뱃지 아이콘/이미지, 알림, 투표·댓글을 기여에 넣는 정책 변경, 타인 프로필의 상세 활동 공개.

## 4. 데이터·API
- **테이블 추가 없음.** 인덱스만 1개 추가: `EditHistory @@index([editorId, createdAt])` (내 활동 쿼리용, 현재 editorId 인덱스 없음 — 리뷰 답신에서 확인). 활동 목록은 `Item(createdById)`, `EditHistory(editorId)`, `Vote(userId)`, `ThemeFollow(userId)` 에서 읽는다.
- `PATCH /api/me` `{ name?, bio? }`: `currentUser()` 필수, 정지 사용자(`isSuspended`) 거부, 길이 검증, 공백 trim, HTML 은 렌더 시 React 가 이스케이프하므로 저장은 원문. 응답은 갱신된 `{ name, bio }`.
- 활동 병합: 두 쿼리를 각각 `take: 30` 으로 가져와 서버에서 `createdAt` 내림차순 병합 후 30건 자르기. **편집 쿼리는 `revision > 1` 만** (문서 생성 시 revision 1 이력이 같이 만들어져 중복되므로). 모든 쿼리에 `item.isRemoved = false`. 쿼리는 서버 세션의 `currentUser().id` 만 사용하고 클라이언트 파라미터는 받지 않는다.
- `PATCH /api/me` 검증은 zod `z.string().trim().min(1).max(30)` / 소개 `trim().max(200)`. 성공 시 `revalidatePath('/me')`, `revalidatePath('/u/' + id)`.

## 5. 결정 사항 (리뷰어가 이견을 낼 지점)
| # | 결정 | 이유 | 대안 |
|---|---|---|---|
| D1 | 투표·댓글은 기여에 넣지 않는다 | 투표는 가중치를 올려 자기강화 루프가 생기고 조작 비용이 가장 낮다 | 댓글만 0.2 가중 |
| D2 | 기여 로그 테이블을 만들지 않는다 | 현재 데이터로 활동 목록을 재구성 가능, 마이그레이션 위험 회피 | `ContributionEvent` 추가 |
| D3 | `/me` 와 `/u/[id]` 를 분리한다 | 본인 전용 정보(투표 내역)를 공개 페이지에 섞지 않는다 | `/u/[id]` 에서 본인이면 확장 |
| D4 | 내 투표 내역은 본인만 본다 | 투표 프라이버시 | 공개 |

## 6. 수용 기준
- `/me` 는 `export const dynamic = 'force-dynamic'` (세션 종속 페이지).
- 정지 사용자는 `/me` 상단에 사유·해제일 배너, 프로필 수정 폼 `disabled`.
- 문서 생성 1건이 활동 목록에 1줄만 나온다 (생성+최초 이력 중복 없음).
- 삭제(isRemoved)된 문서는 활동·투표 목록에서 제외된다.
- 비로그인 `/me` → `/signin` 이동. 로그인 시 5개 영역이 보인다.
- 기여 4건이면 "CONTRIBUTOR 까지 1건" 이 아니라 "다음 뱃지(CONTRIBUTOR, 5건)까지 1건", 최상위(STEWARD)이면 "최고 등급" 표시.
- 가입 3일 된 계정의 투표 가중치가 `voteWeightFor` 값과 화면에서 일치한다.
- `PATCH /api/me`: 31자 이름 400, 정지 사용자 403, 비로그인 401.
- 다른 사용자의 투표 내역은 어떤 경로로도 노출되지 않는다.
- `npm run typecheck`, `npm test` 통과, `badgeProgress` 경계값 테스트(0, 4, 5, 249, 250, 1000).

## 8. 리뷰 요청 (Gemini)
각 항목에 수용/거절을 표시하고, 필수 관점 3가지를 한 줄 이상 다뤄라: **(a) 실패 시나리오**(정지 사용자, 세션 만료, 삭제된 아이템이 활동에 있을 때), **(b) 권한·프라이버시**(타인 데이터 노출 경로), **(c) 멱등성**(프로필 저장 중복 클릭). D1~D4 에 대한 의견도 쓸 것.
