## 2. 적용할 아이디어

### 1) 각주·문서 안 앵커 링크 고치기 (S, 우선)
- **무엇을**: `#` 로 시작하는 링크는 같은 창의 보통 `<a>` 로 렌더하고 `id`·`aria-*` 속성을 넘긴다. 각주 제목은 `h2` 재정의에서 빼고, 라벨을 한국어로 바꾼다.
- **지금 상태**: `src/components/WikiMarkdown.tsx:32-45` 의 `a` 재정의는 `/` 로 시작하지 않는 링크를 모두 외부 링크로 본다. `remarkGfm` 이 만드는 각주 링크 `#user-content-fn-1` 은 새 창(↗)으로 열리고, `id` 가 버려져 "돌아가기"가 갈 곳이 없다. 각주 영역의 숨김 제목 "Footnotes" 는 `h2` 재정의(30행)를 타서 `sr-only` 를 잃고 영어 제목으로 보인다.
- **같은 재정의의 다른 구멍**: `//host/…`(프로토콜 상대 주소)는 `/` 로 시작해 내부 링크로 처리된다. 외부 사이트인데 `rel="nofollow ugc"` 와 ↗ 표시 없이 같은 창에서 열린다. `defaultUrlTransform`(`node_modules/react-markdown/lib/index.js:298-321`)은 `:` 가 없는 주소를 그대로 통과시킨다. `a` 재정의는 `#…` → 보통 앵커, `//…` → 외부 링크의 두 갈래가 필요하다.
- **더 단순한 방법**: `remarkRehypeOptions` 의 `footnoteLabelTagName`(`footer.js:133`)을 `'p'` 로 주면 각주 제목이 `h2` 재정의를 아예 타지 않는다.
- **W50 S 영향**: W47 설계서 5절의 `[^n]` → `[n](#src-n)` 전처리도 같은 이유로 새 창 링크가 된다. S 착수 전에 고쳐야 한다.
- **출처**: `node_modules/mdast-util-to-hast/lib/footer.js:122-249`, `handlers/footnote-reference.js`(설치본). https://github.com/remarkjs/remark-gfm 은 각주 지원을 README 에 적고 있다.
- **어디에**: `WikiMarkdown.tsx`. `ReactMarkdown` 의 `remarkRehypeOptions` 에 `footnoteLabel`, `footnoteBackLabel`, `clobberPrefix` 를 준다. 문서 페이지는 본문·추천 이유·사양을 따로 렌더하므로(`item/[itemSlug]/page.tsx:200-211`) `clobberPrefix` 를 인스턴스마다 다르게 해야 id 가 겹치지 않는다. `footnote-label` id 는 접두어가 붙지 않는다.
- **테스트**: `[^1]` 이 든 본문을 렌더해 `target="_blank"` 가 없는지 확인한다.
- **철학 충돌**: 없음. 출처 표시를 돕는다.

### 2) 차단 도메인 검사를 "새로 추가된 모든 링크"로 넓히기 (S)
- **무엇을**: 구매 링크뿐 아니라 `description`·`specSummary`·`recommendReason` 에 새로 들어온 URL 도 검사한다.
- **지금 상태**: `src/lib/edit-filter.ts:51-54` 는 `purchaseLinks` 만 본다. 본문에 `https://bit.ly/…` 를 쓰면 통과하고 클릭 가능한 링크가 된다.
- **오픈소스 구현**: AbuseFilter 는 편집에서 새로 추가된 링크 전체(`added_links`)를 검사한다. 호스트를 상위 도메인까지 풀어 목록과 대조하므로 서브도메인 차단 방식은 우리 `isBlockedUrl` 과 결과가 같다.
- **출처**: https://github.com/wikimedia/mediawiki-extensions-AbuseFilter/blob/master/includes/BlockedDomains/BlockedDomainFilter.php , https://www.mediawiki.org/wiki/Extension:AbuseFilter/Rules_format
- **어디에**: `checkEdit` 안에서 "이전 URL 집합"과 "이후 URL 집합"을 구매 링크 + 세 본문 필드로 만든다. 문서 생성 라우트(`api/items/route.ts:44`)도 `checkEdit` 을 쓰므로 함께 적용된다.
- **추출 원칙**: 검사기는 렌더러와 같은 URL 을 봐야 한다. AbuseFilter 는 파서 결과에서, BookStack `CrossLinkParser` 는 렌더된 HTML 의 `a[@href]` 에서 링크를 얻는다.
  - 권장: `remark-parse` + `remark-gfm` 으로 만든 mdast 의 `link`·`definition` 노드를 훑는다. `unified`·`remark-parse` 는 `react-markdown` 을 거친 간접 의존성이라, 직접 import 할지 `package.json` 에 올릴지는 구현 때 정한다(미확인).
  - 대안: 기존 `sourceUrls` 정규식(36행)을 보완한다. `i` 플래그(`HTTPS://`), `www.` 시작 주소, `//host` 형태, 끝의 `,`·`.`, 뒤에 붙은 한글 조사를 처리해야 한다. GFM 자동 링크가 한글 앞에서 끊기는지는 확인하지 않았다(미확인). 정규식과 렌더러가 어긋나는 곳이 모두 우회로가 된다.
  - 어느 쪽이든 `//host/…` 는 `new URL(u)` 가 실패하므로 `https:` 를 붙인 뒤 `isBlockedUrl` 에 넘긴다.
- **테스트**: 본문에 새 단축 URL → block, `[x](//bit.ly/a)` → block, 원래 있던 URL → 통과, 필드 사이 이동 → 통과.
- **남는 구멍**: 게시판 글·토론의 링크는 이번에 확인하지 않았다. 되돌리기는 설계대로 제외한다.
- **그대로 둘 것**: 확인 절차. AbuseFilter `Warn` 은 "한 번 경고하고 두 번째 시도는 허용"을 세션에 기억한다. 우리 `ItemForm.tsx:57-62` 는 값이 바뀌면 확인을 무효로 하므로 충분하다. 허용 목록(allowlist)은 지금 목록 크기에서는 필요 없다.
- **철학 충돌**: 없음. 목록은 코드 상수와 커밋으로만 바뀐다.

### 3) 리비전 비교를 필드별 단어 diff 로 보여 주기 (S~M)
- **무엇을**: `?from=&to=` 비교에서 unified patch 원문 대신, 바뀐 필드마다 `<del>`·`<ins>` 로 표시한다.
- **주의(소스 확인)**: jsdiff 의 `diffWords` 기본 토큰 정규식(`extendedWordChars`)에 한글이 없다. 한글은 **음절 하나가 토큰 하나**가 되어 결과가 잘게 쪼개진다. `intlSegmenter: new Intl.Segmenter('ko', { granularity: 'word' })` 를 넘겨야 한다. 실제 출력 품질은 실행해 보지 않았다(미확인).
- **출처**: https://github.com/kpdecker/jsdiff/blob/master/src/diff/word.ts (설치본 `node_modules/diff/libesm/diff/word.js:23,48` 도 같다)
- **어디에**: `history/page.tsx:94-103`. `changedFields`(`wiki.ts:72`)로 필드를 고르고 필드별로 `diffWords` 를 부른다. **`buildDiff` 는 바꾸지 않는다.** 결과가 `EditHistory.diff` 에 저장되고 `diffDelta`(기여 최소 변경량)가 그 형식에 의존한다. 긴 본문에 대비해 `maxEditLength` 나 `timeout` 을 주고, `undefined` 가 오면 지금의 원문 diff 를 보여 준다. 새 의존성은 없다.
- **접근성**: 색만으로 구분하지 않는다(`<del>` 취소선, `<ins>` 밑줄).
- **철학 충돌**: 없음.

### 4) 검색에서 이름 일치를 먼저 보여 주기 (S)
- **무엇을**: 이름에 검색어가 있는 문서를 먼저, 본문에만 있는 문서를 뒤에 둔다. 각 묶음 안에서는 지금처럼 점수순이다.
- **지금 상태**: `search/page.tsx:31-44` 와 `api/search/route.ts:25-33` 은 이름·본문 일치를 섞어 점수순으로 자른다(30건, API 기본 10건). 점수가 낮은 문서는 이름이 정확해도 잘릴 수 있다.
- **오픈소스 구현**: BookStack 은 검색어 색인에서 제목 단어에 본문보다 훨씬 큰 가중치(×40)를 준다.
- **출처**: https://github.com/BookStackApp/BookStack/blob/development/app/Search/SearchIndex.php (`entityToTermDataArray`)
- **어디에**: 위 두 파일. 색인 테이블 없이 쿼리 두 번(이름 일치, 그다음 이름 제외 본문 일치)이면 된다. 두 곳이 같은 함수를 쓰게 한다. `same=1` 경로는 그대로 둔다.
- **철학 충돌**: 없음. 검색 노출 순서만 바꾸며 점수 계산에는 손대지 않는다. 규칙은 두 줄이라 공개하고 재현할 수 있다.

### 5) 위키링크 테이블: "원본 단위로 지우고 다시 넣기" (M, W50+, 지금 하지 않음)
- **무엇을**: 문서를 저장할 때 그 문서가 보내는 링크 행을 지우고 다시 넣는다. 전체 재구축 함수를 함께 둔다.
- **오픈소스 구현**: BookStack `ReferenceStore::updateForEntity` / `updateForAll`. MediaWiki `LinksTable::update` 는 추가·삭제분만 반영하는 증분 방식인데, 우리 규모에는 BookStack 방식이 단순하다.
- **우리가 다르게 할 점**: BookStack 은 **실제 문서로 해석된 링크만** 저장한다(`CrossLinkParser::extractLinkedModels`). 우리는 빨간 링크와 "만들어 주세요" 집계가 있으므로 대상 **제목**을 저장해야 한다.
- **출처**: https://github.com/BookStackApp/BookStack/blob/development/app/References/ReferenceStore.php , https://github.com/wikimedia/mediawiki/blob/master/includes/Deferred/LinksUpdate/LinksTable.php
- **어디에**: `src/lib/wikilinks.ts:37` 의 `ponytail:` 한계(문서 3천 개 또는 응답 1초)에 닿을 때. 추출은 기존 `extractWikiLinks`, 갱신 지점은 생성·편집·되돌리기 라우트. 스키마 추가라 G-사람 선행이다. 공백이 낀 `[[ 이름 ]]` 을 역링크에서 놓치는 알려진 한계도 함께 풀린다.
- **철학 충돌**: 없음. 역링크 수는 점수·인기에 넣지 않는다(W49 설계서 8절).

## 3. 채택하지 않을 것
| 대상 | 이유 |
|---|---|
| 순찰(patrol) 표시 | 기본값은 관리자(sysop)만 "검토함"을 표시한다(https://www.mediawiki.org/wiki/Help:Patrolled_edits ). 운영자 권한 기능이라 W49 설계서 0절 거름망 1에 걸린다. 계산형 변경 태그로 대신한다 |

| BookStack 식 검색어 색인 테이블 | 지금 규모에는 아이디어 4의 쿼리 두 번으로 충분하다 |

| 문서 보호·권한 | 규칙 계산형 보호 수준이 이미 있다. Wiki.js·Outline·Docmost·DokuWiki 의 권한 구현은 읽지 않았다(미확인) |
